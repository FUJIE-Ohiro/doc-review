# 文档校阅

「文档校阅」是一款面向「英文科技论文写作课程——论文分析合集」的 **本地、批量、只读** `.docx` 排版初筛器。支持 **Windows、macOS、Linux**，无需 Microsoft Word、联网、账号或第三方 Python 包。软件不会改动学生原稿。

> **定位**：这是编辑团队的格式初筛工具，不是论文质量评分器，也不是 100% 准确的 Word 排版渲染引擎。报告中「未发现明显异常」**不等于通过终审**。

## 功能和文件

可检查：A4 和 2.54 cm 页边距、正文中英文字体与字号、行距、段前段后、首行缩进、对齐方式、一级和二级章节标题、图表标题、部分编号/参考文献对应、修订记录和页码字段。具体以本仓库 `word_audit.py` 中的规则为准。

| 文件 | 用途 |
|---|---|
| `word_audit.py` | 审校主程序，Python 3.9+，仅依赖标准库 |
| `启动_Windows.bat` | Windows 图形界面启动器；失败时可改用文本输入 |
| `启动_macOS.command` | macOS 终端交互启动器；不依赖 tkinter |
| `examples/` | 三份测试用 Word 稿件，并非实际学生论文 |
| `tests/` | 自动化测试 |
| `.github/workflows/tests.yml` | 提交代码后在 Windows/macOS/Linux 的自动化测试配置 |

## 一、Windows 10 / 11：最简单的使用方法

1. 在 GitHub 项目页面选 **Code → Download ZIP**，下载后 **完整解压**，不要直接在 ZIP 里双击。
2. 安装 [Python 官方版本](https://www.python.org/downloads/windows/)（建议 3.11 或更新版本；最低 3.9）。Windows 安装时建议选择 **Add python.exe to PATH**。
3. 将所有待检查的 `.docx` 文档放进一个文件夹，比如 `D:\论文合集\G1`。子文件夹默认不会被扫描。
4. 双击 **`启动_Windows.bat`**，在弹出的窗口中选择稿件文件夹。若 tkinter 图形界面不可用，启动脚本会提示输入或粘贴文件夹路径。
5. 选择报告保存目录（如果取消，报告默认保存在稿件文件夹的上级目录）。
6. 打开程序生成的 `审校结果_年月日_时分秒/审校报告.html`；也可以用 Excel 打开 CSV。

**命令行替代**（PowerShell 或命令提示符进入程序所在文件夹）：

```powershell
py -3 word_audit.py --input "D:\论文合集\G1" --output "D:\论文合集\报告"
```

如果没有 `py` 命令，将 `py -3` 改成 `python`。

## 二、macOS：最简单的使用方法

1. 在 GitHub 页面选择 **Code → Download ZIP**，解压整个文件夹。
2. 打开「终端」，执行 `python3 --version`；确保为 **Python 3.9 或更新版本**。如未安装，可从 [Python 官网](https://www.python.org/downloads/macos/) 安装。
3. 将学生 `.docx` 放在同一文件夹，例如 `~/Documents/论文合集/G1`。
4. 在 Finder 中打开下载的项目文件夹，双击 **`启动_macOS.command`**。它会打开终端，**将稿件文件夹直接拖进终端窗口**，按回车即可。路径里有空格或中文也可以。
5. 在提示位置打开 `审校结果_.../审校报告.html`；CSV 可用 Excel 或 Numbers 阅读。

如果 macOS 提示 `.command` 没有执行权限，打开终端并输入 `chmod +x `（末尾有空格），把 `.command` 文件拖入终端，然后回车。再双击尝试。

如果系统安全设置阻止来自互联网的脚本，请先检查代码来源；可以**无需双击**，直接在终端进入项目文件夹后运行：

```bash
python3 word_audit.py --input "$HOME/Documents/论文合集/G1"
```

也可以用 `python3 word_audit.py --gui` 尝试图形界面，**但部分 macOS Python 安装未包含 tkinter**，建议优先使用 `.command` 启动方式。

## 三、所有系统都可用的命令

```bash
python3 word_audit.py --input "/存放docx文件的文件夹" --output "/保存审校报告的文件夹"
```

- `--input`：**必填**的文件夹路径；直接运行且不提供此参数时，默认尝试 tkinter 图形界面。
- `--output`：可选；报告将创建在该位置下的新文件夹，不覆盖原有报告。
- 只扫描指定文件夹中一级目录的 `*.docx`，不会递归子文件夹，跳过 Word 临时锁文件 `~$...docx`。
- 不支持旧版 `.doc`、`.pdf` 或 WPS 私有格式；先在 Word/WPS 中另存为 `.docx`。

## 四、报告说明

每次运行生成新的 `审校结果_YYYYMMDD_HHMMSS` 文件夹：

- **`审校报告.html`**：浏览器查看每篇论文问题，按文件名定位。
- **`稿件汇总.csv`**：显示每篇论文的「错误」「待复核」「提示」数量。
- **`问题明细.csv`**：列出文件、等级、问题类别、段落位置、检测值、规范值、说明。
- **`审校元数据.json`**：运行时间与统计信息。

**判读原则**：「错误」= 读取到与规则冲突的排版属性；「待复核」= 信息不足或启发式判断；「提示」= 一般提醒。即使没有检测到错误，也必须检查最终 Word/PDF 的视觉效果。

## 五、适用的课程稿件标准

针对编辑团队当前发布的中文版规范：**正文中文宋体、英文和数字 Times New Roman，12 pt，A4，四边页边距 2.54 cm，正文两端对齐、首行缩进 2 字符、单倍行距，中文主标题黑体 16 pt 居中，一级/二级标题中文宋体 12 pt 加粗左对齐**，对应段间距要求。作者姓名及所属单位使用中文。图表标题 10 pt。个人稿件暂不加页码。新版本通知若变化，需要相应更新代码规则。

## 六、可靠性和隐私边界（请阅读）

- Word `.docx` 内部是 Office Open XML；程序直接读取属性，不需要安装 Word，因此 **Windows/macOS 两端的核心检查逻辑一致**。
- 字体继承、主题字体、字符样式、中文字体替换、文本框、页眉页脚、表格、脚注、自动多级编号、修订与复杂引用可能出现漏检或误报。
- 无法直接验证图片清晰度、实际分页、排版美感、DOI 真实性、文献学术水平、是否抄袭或科研内容是否正确。
- 程序离线运行，无网络请求、不修改原稿。报告包含部分段落文本和文件名，**请勿将真实学生稿件或包含未发表数据的审校报告上传到公开 GitHub**。
- 自动化测试仅验证若干构造样本；GitHub Actions 绿灯并不代表所有实际文档都能 100% 准确解析。

## 七、副主编建议流程

1. 10 月 30 日（星期五）12:00 前收齐组内 `.docx` 稿件，按小组整理到一个文件夹。
2. 批量运行工具，优先处理「错误」，再查看「待复核」。
3. 人工审阅研究深度、三篇论文的横向比较、英文例句及其中文分析，核对引用原文。
4. 在 Word 的「审阅 → 修订/批注」中将修改意见反馈给作者，作者自行排版修改。
5. 11 月 1 日（星期日）12:00 前完成组内审校、修改沟通并汇总提交主编；11 月 1–2 日继续统一整理，保留初稿与修改稿便于追踪。

## 八、开发者：运行测试

```bash
python3 -m unittest discover -s tests -p 'test_*.py' -v
```

代码仅依赖 Python 标准库。测试样本在 `examples/`；跨平台 GitHub Actions 会在代码上传后由 GitHub 执行（是否实际通过，请以 Actions 页面结果为准）。

## 常见问题

**Q：检查工具说“待复核”，是不是不合格？** 不是，只表示需要人工确认。

**Q：可以让程序自动改格式吗？** 当前版本故意不修改原稿，以符合课程要求学生独立掌握排版的教学目的。

**Q：这个检查能代替副主编审稿吗？** 不能。它只能降低重复性的格式检查工作量。

**Q：运行时卡在选择文件夹？** 请确认选的是**文件夹**而不是某一个 `.docx`，并确认该文件夹里确实存在 `.docx` 文件。
